Accessibility and interaction pass on the editor chrome, from a design critique
that measured the UI rather than looking at it.

**Contrast.** Every secondary label — the palette group headings, the element and
icon counts, the inspector's field labels, the type name, the X/Y/W/H keys — used
the theme's faintest text token at 10px, measuring 2.2–2.4:1 against the panel.
That is below WCAG AA for all nineteen of them. They now use the readable
secondary token at 11–11.5px. The lowest, the tab counts, went from 2.2:1 to
4.9:1. The wireframe you draw is deliberately untouched: its placeholder text and
greeked paragraphs are faint because they depict faint things.

**Pointer targets.** Toolbar buttons were 23px tall, one pixel under the 24px
floor in WCAG 2.2 SC 2.5.8; the zoom label was 14px and the modifier chips 19px.
All chrome controls are now at least 24px, most 26px.

**Keyboard.** The toolbar and the palette were mouse-only — divs with click
handlers, unreachable by Tab. They are now buttons with roles, focusable, and
they respond to Enter and Space. There were no focus styles anywhere in the
editor; there is now one ring, on controls only, never on the drawing surface.

**Motion.** Opening the palette used to happen in a single frame because the list
was `display: none`; it now moves 130ms on transform and opacity. Selecting an
element still snaps — you do that hundreds of times in a session and a panel
sliding on every click would be noise — but the inspector's contents fade in, so
it no longer flashes. Buttons take a small push on `:active`. All of it collapses
under `prefers-reduced-motion`.

**Copy.** The empty canvas said "drag a widget from UI elements on the left"; the
panel has been called Elements for two versions. The destructive action no longer
sits in the same row, at the same weight, as "Edit text".
