Wireframes come out the size of what is in them.

Everything here is one complaint: the output did not look drawn, it looked assembled. A mail screen with a 220px sidebar stretched to 413, a subject line ellipsised to "Quarterly ...", a grey bar where a divider should have been, and a pool of empty paper under every list.

- **Boxes are the size of what is in them.** A four-row table used to be drawn at the height a twelve-row one would need. Lists, tables, key/value pairs, menus, radio groups and navs are now measured from the rows you wrote.
- **`(fill)` works downwards as well as across.** In a row it takes the leftover width, as before. In a column it now takes the leftover height, which is what lets the content pane of a screen reach the bottom of it. One rule: a box marked `(fill)` is sized by its container rather than by its contents.
- **Two boxes side by side in a row come out the same height.** A sidebar next to a taller content column looked like something had gone wrong, because it had. Controls are left alone — a search box does not grow to match the avatar beside it.
- **A table cell holding nothing but `[x]`, `[ ]` or `*` draws a real checkbox or star**, and that column narrows to the width of the mark. Cells claimed an equal share each, so an empty checkbox column took as much room as the subject line. The decision is made per column, so a star column with blanks in it still lines up down the table.
- **A plain divider draws a hairline.** It has been a solid grey bar the width of the board since the day the board shipped. A rule of mine grew the 1px line to fill its element, and the fix in 1.5.2 was written at the same specificity as the rule it was meant to beat, so it lost on source order. I checked that one against the palette thumbnail, which is not in the same part of the page.
- **The genie is told all of it**, with an app shell in the prompt to copy from. The board prompt and the chat prompt read from one shared set of rules, so they cannot describe the DSL differently again.

Under it all, the three places that turned a parsed line into an element are now one. Content sizing had landed in only the third of them, so a table nested inside a column hugged its rows while the same table pasted on its own kept guessing.
